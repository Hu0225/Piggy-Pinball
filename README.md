# 好运弹珠社 · PIGGY PINBALL

根据参考图制作的复古小猪街机弹珠小游戏，使用原生 HTML、CSS 和 Canvas，无需安装依赖。

开发接手先读 [AGENTS.md](AGENTS.md)，其中整理了源码入口、已确认约束和必要检查；本文件提供详细玩法与技术说明。

## 在线游玩

打开 [好运弹珠社](https://hu0225.github.io/Piggy-Pinball/) 即可直接游玩，支持电脑和手机。

## 直接游玩

双击 `好运弹珠社.html`，即可在现代浏览器中离线游玩。所有样式、绘图、音效和物理代码均内嵌在这一个 HTML 文件中。

- 初始有 990 颗游戏弹珠。底部“投珠 N 颗”按显示数量立即投入，“设置数量”仅调整每次投入量，不扣珠。投入至少 1 颗即可激活游戏，每局总本金最多 99 颗；取消与退款入口暂不开放。
- 首次投珠成功后立即自动从 2–12 倍整数倍率中等概率抽取，并播放短暂倍率动画，无需再点击确定。之后、发射前仍可点投珠按钮加注，所有投入都计入本局本金，倍率和亮灯轨道保持不变。亮灯数量为：2 倍有 4 条，3 倍有 3 条，4–6 倍有 2 条，7–12 倍有 1 条。亮灯位置随机且分散，避免相邻扎堆。
- 台面与控制台之间是与整机统一的复古暖色投珠仓：暖杏外壳、香槟金结构件、深橄榄绿内槽，以及带暖色反光的透明低挡边；保留圆润造型、分流槽和状态动效，入口使用暖金灯光，右端以橙色提示分流和就绪状态。弹珠从左侧入口进入上层弧形滑槽，首颗顺坡经分流口进入右侧发射位，其余从分流口落入下层水平储珠盘；之后加注的弹珠全部进入储珠盘。银珠保持固定大小，在低矮透明挡边后按落料动量自然铺开、碰撞和堆叠，加注保留已收集的珠子，大量投珠从挡边后的底层持续收纳。美术更新保留原有投珠几何、物理与玩法规则。每颗进入收集区时立即获得 1 独立积分，首投 1 颗得 0 分，首投 10 颗得 9 分，再加注 5 颗共得 14 分。全部弹珠到位后才能发射。
- 独立积分与积分卡分开记录，不影响本金、倍率或中奖返珠；本局发射后即使未中奖，已获得的独立积分仍保留。积分卡继续由中奖返珠结算发放。
- 每局由 1 颗判定珠决定全部本金的结果。沿用原来的拉杆和力度进度条样式：下拉蓄力、松手发射；也可按住空格键、橙色按钮或台面蓄力。弹珠回到发射位后可再次拉动。
- 力度以百分比显示，力度越大初速度越快。弹珠运动期间不能重复拉杆或加注。
- 同力度可复现轨迹与落点，亮灯目标和倍率仍然每局随机。最近 3 次发射的力度与轨道记录独立保存在当前浏览器，跨局与刷新保留；桌面侧栏可查看，手机在“？”的发射说明页查看上一发。台面轨道从左到右编号 01–10。
- 判定珠落入亮灯轨道时，返还“总本金 × 本局倍率”颗弹珠，返珠已包含本金；未亮灯轨道不返珠。例如先投入 5 颗、确定 6 倍后再加注 5 颗，总本金为 10 颗，命中返还 60 颗并获得 2 张积分卡。
- 本局中奖返珠每满 30 颗得 1 张积分卡，30 / 60 / 90 颗对应 1 / 2 / 3 张，无 3 张上限；余数不跨局累计。积分卡在整局结算时一次发放。
- 积分卡可在礼品柜兑换游戏内的小猪贴纸、好运挂件、小猪公仔和奖杯，分别需要 1 / 3 / 6 / 12 张卡。余额和藏品保存在当前浏览器。
- 刷新页面时保留已结算奖励与独立积分，未结算回合退回全部本金，同时撤回该局已经入账的独立积分，不能通过反复刷新累积积分。旧版本存档保留余额、积分卡和藏品，独立积分初始为 0，并按旧规则处理尚未结束的回合。
- 弹珠余额为 0 且没有进行中的回合时，可领取 50 颗补给继续游玩。
- 台面在倍率确定后显示“命中可返”的本金 × 倍率数值，加注时同步更新；落袋结算后改为显示“本局返珠”的实际结果。中奖槽位显示本局倍率，未亮灯槽位不显示中奖倍率。
- 按 M 或右上角喇叭开关音效。手机端使用无滚动的单屏布局：余额、台面、投珠槽和底部拉杆同屏显示，直接点击底部投珠按钮投入或加注，点击“？”翻页查看玩法。页面根据可视高度和安全区适配较短的 WebView，调节数量时不会弹出手机键盘。
- 音效提高了输出增益，使用压缩器控制连续碰撞叠加的峰值。顶部手机图标独立开关震动，设置会保存；拉杆跨越力度档位时轻震，发射和钉子、边墙、隔板碰撞按力度使用不同脉冲。
- iOS Safari 音效会在点击、触摸结束或拉杆松手时解锁；音频恢复期间短暂保留发射和提示音，切回前台后尝试恢复中断的音频。支持 Audio Session API 时使用 `playback` 会话，解决较新 iOS 静音模式下 Web Audio 无声的问题，关闭音效或切后台会释放会话。该模式可能暂停其他应用的音乐；旧版 iOS 若仍无声，请关闭手机静音模式并检查媒体音量。[WebKit 说明](https://bugs.webkit.org/show_bug.cgi?id=237322) · [音频会话说明](https://developer.mozilla.org/en-US/docs/Web/API/AudioSession/type)

网页震动使用 `navigator.vibrate`，通过脉冲时长与节奏区分触感，不能直接调节马达振幅；实际效果取决于硬件、浏览器和系统设置。iOS Safari 与 iOS WebView 不支持该网页接口，界面会提示当前浏览器不支持。[MDN 接口及兼容性](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)。当前发布的是 HTML 网页，放入微信 WebView 不会自动获得原生小程序震动能力；`PinballHaptics` 的显式 `nativeHaptics` 适配器可供具备原生能力的宿主接入。

## 修改源码

`dist/index.html` 是页面结构，`dist/style.css` 是响应式外观，`dist/app.js` 是绘图和交互，`dist/physics.js` 是独立物理引擎，`dist/rules.js` 管理回合、返珠、独立积分、积分卡与兑换，`dist/feeder.js` 管理投珠槽分流动画及逐颗入洞事件，`dist/haptics.js` 管理触感强弱、节流及兼容，`dist/audio.js` 管理合成音效、用户手势解锁和音频恢复。没有第三方图片、字体、脚本或网络请求。

发射出口使用 90° 圆弧，绘制与物理共用 `PinballPhysics.LAUNCH_RAIL` 几何参数。弹珠沿切线离轨，轨道内按重力转换势能与动能，离轨时不额外施加横向速度。10%临界档在顶部极近处做微小耗能，避免理想零速状态下悬停；视觉到顶后仍按重力回落，不会被额外送出轨道。
出口边缘使用圆头、平滑外展的唇边及渐变底色，保持出口敞开。

台面沿用原来的 8 排交错布局，共 68 颗钉子，位置、间距和半径与原版一致。碰撞恢复原版反弹：钉子的法向恢复系数为 0.74、洞口圆头为 0.4，保留切向速度，不再额外乘以 0.15 衰减。力度直接控制发射初速度，以起点到最高出口的高度差校准10%临界能量；低于临界档会在管内回落，11%–100%正常出轨并增强速度，当前投珠舱满力初速度约为2212像素/秒，十条轨道均可到达。物理过程不读取亮灯轨道、倍率、奖励或弹珠编号，也不预选目标洞口。管内回落不参与落袋结算；正式发射必须真实跨过槽底才结算，不因超时直接结算。

同力度的轨迹与落点不受回合数、球编号及中奖目标影响。原版密集交错钉子和强反弹会放大微小力度差异，因此力度增加不保证落点向同一方向移动，也不保证只跨一个洞口。请通过观察轨迹和上一发记录练习；初速度映射更新后使用新的练习记录版本，避免旧力度记录的落点误导瞄准，弹珠余额、积分卡与收藏仍然保留。

修改后运行 `node build-single.mjs`，重新生成单文件 HTML。

## 本地预览与验证

在本目录运行 `python -m http.server 4173 --directory dist`，浏览器访问 http://localhost:4173 。

运行 `node test-physics.cjs` 验证初速度随力度递增、1%–9%管内回落、10%临界到顶回落、11%–100%正常出轨、轨道圆弧、离轨切线及速度连续性，以及所有奖励槽。另检查管内回落和正式发射跨球编号与帧率的可重复性、回落不结算及正式发射真实触底结算。保留物理引擎的 10 球并发验证；实际玩法每局仅有一次正式发射机会。

运行 `node test-launch.cjs` 验证实际应用的管内操作锁定、连续低力度重试、出轨计次、回落后本金与积分保持、练习记录版本及刷新恢复。

运行 `node test-rules.cjs` 验证投珠激活、各档亮灯数量与分散布局、倍率锁定、发射前加注、逐颗独立积分与防重复入账、收集完成后才可发射、单次发射限制、总本金结算、积分卡阈值、礼品兑换，以及新旧亮灯配置的存档恢复和未结算积分回滚。

投珠仓采用上层独立弧形滑槽和下层水平储珠盘。上层沿用原储珠盘左高右低、右端逐渐放平的曲线形状，按滑槽空间缩放；下层盘底和透明挡边保持水平，珠子依靠落料动量与碰撞自然铺开。珠子从左上入口进入滑槽，首颗顺坡进入右侧发射位，其余经右端导片向左下落到珠堆表面，随即参与碰撞。滑槽底面与储珠盘底面分别由 `PinballFeeder.CHUTE` 和 `PinballFeeder.TRAY` 定义；槽内固定珠径并保持出珠间距，出口堵住时保留可见珠并暂停输珠，下盘腾空后再继续，接受落珠后才计分。减少动态效果和切后台时共同快进上下层物理，保持全部计分完成。

入口通过连续圆角弯头接入弧槽；右端由固定背梁和铰座连接分流组件、机壳与发射导轨。导片保持固定形状并绕轴开合，桥板等长滑回左槽，上下边框沿用同一厚度和侧剖面。

运行 `node test-feeder.cjs` 验证入口遮挡、曲面支撑与珠间距、入口法线连续性、出口平切线、全程顺坡的首珠分流、加注收集、1 / 10 / 99 颗投珠的准确入洞事件、分流桥时序、帧率无关性，以及中断与防重复回调。运行 `node test-collector.cjs` 验证水平盘底支撑、静珠无水平漂移、上方落珠连续性、槽底上壁、珠间碰撞、自然堆积、满量收纳、加注和帧率一致性。

运行 `node test-haptics.cjs` 验证三档反馈、拉杆档位、频率限制、用户激活、隐藏页面、开关、取消和不支持接口时的兼容处理。自动测试验证调用逻辑，实际震感须在支持的手机上体验。

运行 `node test-audio.cjs` 验证异步音频解锁、中断恢复、静音与后台切换、待播音效时效及 Safari 音频会话兼容。自动测试不能代替 iPhone 真机听音检查。

## GitHub Pages 部署

`.github/workflows/pages.yml` 会在 `main` 分支的游戏或测试文件发生变化时，检查脚本语法，运行物理、规则、投珠分流、触感和音效测试，并将 `dist/` 发布到 GitHub Pages。也可以在 GitHub 的 Actions 页面手动运行 “Deploy game to GitHub Pages”。

仓库 Settings → Pages 的发布来源使用 **GitHub Actions**。
